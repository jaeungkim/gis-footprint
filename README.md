# Footprint

Footprint는 지도에서 위성영상을 찾고, 필요한 영역만 잘라 사고, 분석까지 맡기는 위성영상 마켓플레이스입니다. 운영자는 같은 플랫폼의 백오피스에서 카탈로그 수집, 주문 처리, 촬영 요청, 가격, 사용자를 관리합니다.

Planet Explorer나 UP42 같은 상용 위성영상 플랫폼의 구조를 따르고, 실제 Sentinel-1·2 위성의 메타데이터(STAC)와 실제 영상(COG)을 씁니다.

## 핵심 시나리오

| 시나리오 | 고객이 하는 일                                                                              | 운영자가 하는 일                           |
| -------- | ------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 찾기     | 관심 지역을 그리거나 올리고, 기간·센서·운량으로 영상을 검색해 지도에서 비교                        | 외부 카탈로그에서 영상을 수집하고 공개 여부 관리 |
| 사기     | 영상을 관심 지역 크기로 잘라 장바구니에 담고, 견적을 보고 주문한 뒤 처리 상태를 따라가다 다운로드 | 주문 승인과 반려, 실패 건 재처리, 가격 정책 관리 |
| 요청하기 | 원하는 영상이 없으면 지역과 기간을 지정해 신규 촬영을 요청                                      | 요청을 검토하고 일정을 배정한 뒤 결과를 연결     |
| 지켜보기 | 관심 지역을 등록해 두고 새 영상이 들어오면 알림을 받음                                           | 주기 수집 작업과 알림 발송 현황 확인            |
| 분석하기 | 영상에서 선박·건물을 찾거나 두 시점의 변화를 탐지해 지도에 겹쳐 봄                                | 분석 작업 현황 확인                           |

고객 예시: 농작물 작황을 보는 농업 기업, 항만 선박 동향을 보는 해운사, 공사 진척을 확인하는 건설사, 재해 피해를 산정하는 보험사, 연구 기관.

## 사용자와 역할

| 역할               | 할 수 있는 일                                                         |
| ------------------ | --------------------------------------------------------------------- |
| 고객 `CUSTOMER`    | 영상 탐색, 장바구니와 주문, 다운로드, 촬영 요청, 관심 영역 알림, AI 분석 |
| 운영자 `OPERATOR`  | 백오피스에서 주문·상품·촬영 요청 처리, 수집 실행, 대시보드 조회          |

## API 규칙

- 모든 경로는 `/api` 아래에 둡니다. 관리자 API는 `/api/admin/*`입니다.
- 에러는 RFC 9457 Problem Details(`application/problem+json`)로 반환하고, 필드 오류는 `errors` 배열에 담습니다.
- 목록은 커서 페이지네이션(`limit`, `cursor`, 응답의 `nextCursor`)을 씁니다. 백오피스 테이블만 페이지 번호(`page`, `pageSize`, `total`)를 씁니다.
- 시각은 UTC ISO 8601로 저장하고 응답합니다. 사용자가 입력하는 날짜는 한국 시간 기준으로 해석합니다.
- 중복되면 안 되는 생성 요청(`POST /api/orders`)은 `Idempotency-Key` 헤더를 받습니다.
- 공간 데이터는 GeoJSON(RFC 7946, EPSG:4326)으로 주고받습니다.
- web의 API 타입은 OpenAPI 명세에서 생성합니다(`pnpm --filter @repo/web gen:api`).

### 1. 카탈로그 적재

**필수**

- 서버 시작 시 `data/catalog/items.json`(STAC ItemCollection)을 읽어 카탈로그에 적재합니다.
- 유효하지 않은 Item은 제외하고 id와 사유를 로그로 남깁니다. 불량 Item이 있어도 서버는 정상 기동하고, 마지막에 적재 요약(적재 n건 / 전체 m건)을 남깁니다.
- STAC 속성을 플랫폼 모델로 정규화합니다: 센서(EO/SAR), 위성, 촬영 시각, 운량(EO만), 해상도(GSD), footprint, 썸네일.
- `GET /api/scenes/:id`로 단건을 GeoJSON Feature로 조회합니다. 없으면 404입니다.
- 카탈로그는 리포지토리 인터페이스 뒤에 둡니다. 처음에는 메모리로 구현하고, 6단계에서 Postgres, 16단계에서 PostGIS 구현으로 바꿉니다.

**심화**: 검증 로직 단위 테스트, 제외 통계를 `/api/health`에 노출

**학습 포인트**: GeoJSON 규칙(RFC 7946의 좌표 순서, 링 닫힘, 오른손 법칙), STAC Item 구조(properties, assets, links, eo·sar·proj 확장), EPSG:4326, 스키마 검증

### 2. 영상 검색 API

**필수**

- AOI와 겹치는 영상을 찾는 검색 API를 설계하고 구현합니다. [STAC API Item Search](https://github.com/radiantearth/stac-api-spec/tree/main/item-search) 규격을 참고합니다.
- 검색 조건:
  - AOI (GeoJSON Polygon 또는 MultiPolygon)
  - 촬영 기간 (한국 시간 기준 날짜, 양끝 포함)
  - 센서 (복수 선택)
  - 최대 운량
  - 최대 해상도(GSD)
  - 위성
- 정렬: 최신순(기본), 커버리지 높은순, 운량 낮은순
- 응답은 GeoJSON FeatureCollection입니다. 각 영상에는 AOI 중 그 영상이 덮는 면적(km²)과 비율(%)을 넣고, 다음 페이지 커서를 함께 줍니다.
- 잘못된 요청에는 400 Problem Details를 반환합니다.
- 필터와 커버리지 계산 단위 테스트를 작성합니다.

**심화**: bbox 사전 필터와 성능 측정, GET 방식 검색과 비교, STAC API 호환 엔드포인트(`/api/stac/search`)

**학습 포인트**: 교차 판정(bbox 사전 필터와 정밀 교차), 구면 면적과 평면 면적, 시간대와 날짜 경계, STAC API, 커서와 오프셋 페이지네이션

### 3. 탐색 화면

**필수**

- 지도, 필터 패널, 결과 목록으로 된 탐색 화면을 만듭니다.
- 샘플 AOI를 고르면 지도가 그 영역으로 이동하고 AOI를 표시합니다.
- 결과 footprint를 지도에 그립니다. 목록에서 hover·클릭하면 지도에서 강조하고, 지도에서 클릭하면 목록의 해당 항목으로 스크롤합니다.
- 결과 항목에는 썸네일, 위성, 촬영 시각(한국 시간 표시), 운량, 커버리지를 보여 줍니다.
- 검색 조건은 URL에 유지합니다. 새로고침하거나 링크를 공유해도 같은 결과가 나와야 합니다.
- 로딩, 결과 없음, 에러 상태를 보여 줍니다.
- 결과는 무한 스크롤로 이어서 불러옵니다.

**심화**: 선택한 영상의 썸네일을 footprint 위에 겹쳐 보기, footprint가 많을 때의 렌더링 성능, 모바일 레이아웃

**학습 포인트**: MapLibre의 source·layer·feature-state, EPSG:3857과 4326, URL 상태와 지도 상태의 분리, 서버 상태 캐싱

### 4. 인증과 역할

**필수**

- 회원가입, 로그인, 로그아웃. 비밀번호는 argon2로 해시합니다.
- httpOnly 쿠키 세션을 쓰고 세션은 Redis에 저장합니다.
- 역할은 CUSTOMER, OPERATOR, ADMIN입니다. API는 Guard와 역할 데코레이터로, web은 middleware로 보호합니다.
- `/admin` 레이아웃(사이드바, 헤더)을 만들고 권한이 없으면 접근을 막습니다.
- seed로 역할별 데모 계정을 만듭니다.

**심화**: 비밀번호 재설정(메일은 콘솔 출력으로 대신), 로그인 실패 횟수 제한

**학습 포인트**: 세션과 JWT 비교, RBAC, SameSite 쿠키와 CSRF, 비밀번호 해싱

### 5. 사용자 관리

**필수**

- 고객: 내 정보 수정, 비밀번호 변경, 탈퇴(소프트 삭제)
- 백오피스:
  - 사용자 목록 (이름·이메일 검색, 역할·상태 필터, 정렬, 페이지 번호)
  - 사용자 상세와 역할 변경
  - 정지와 해제 (정지하면 그 사용자의 세션을 즉시 끊음)
  - 초대 링크로 운영자 추가 (일회용, 만료 있음)
- 감사 로그를 도입합니다. 운영자와 관리자의 변경 작업을 interceptor로 자동 기록하고, 백오피스에서 조회합니다.

**심화**: 조직(기업 고객) 계정, 조직 멤버 관리, 조직별 계약 단가(7단계와 연결)

**학습 포인트**: 일회용 토큰, 소프트 삭제와 개인정보 처리, 세션 무효화, interceptor 기반 감사 로그

### 6. 상품 관리와 수집

**필수**

- 카탈로그를 Postgres에 저장합니다. footprint는 JSON 컬럼에 두고 공간 검색은 메모리 인덱스로 계속합니다.
- worker(BullMQ)를 도입합니다. 수집 작업은 기간, 지역, 컬렉션을 받아 STAC API에서 Item을 가져오고, 검증한 뒤 upsert합니다.
- 수집 이력(IngestRun)에 상태, 신규·갱신·제외 건수, 제외 사유를 남깁니다.
- 백오피스:
  - 상품 목록 (검색, 필터, 정렬)
  - 상품 상세 (지도, 메타데이터, 원본 STAC JSON)
  - 공개와 숨김
  - 수집 실행과 이력 화면

**심화**: 실패한 수집 재시도, 수집 진행률 실시간 표시

**학습 포인트**: 외부 API 페이지 순회(STAC `next` 링크), 멱등 upsert, 증분 수집, 배치 작업과 재시도

### 7. 장바구니와 가격

**필수**

- 고객: 영상을 장바구니에 담을 때 잘라낼 AOI를 지정하고, 잘린 영역(footprint와 AOI의 교집합)을 미리 봅니다.
- 견적은 잘린 면적 × 단가이고, 최소 주문 면적을 적용합니다. 견적은 서버에서만 계산합니다.
- 백오피스: 가격 정책 관리 (센서·해상도 등급별 km² 단가, 최소 면적, 유효 기간)

**심화**: 조직 계약 단가 적용, 장바구니에 담은 뒤 가격이 바뀐 경우 처리

**학습 포인트**: 공간 clip, 금액 계산(정수 원 단위, 반올림 규칙), 가격 버전과 유효 기간

### 8. 주문과 처리

**필수**

- 고객:
  - 장바구니로 주문 생성 (`Idempotency-Key`)
  - 주문 내역과 상세
  - 상태 실시간 갱신 (SSE)
  - 완료된 주문 다운로드 (만료되는 서명 URL)
- 주문 시점의 가격을 스냅샷으로 저장합니다.
- worker가 외부 처리 시스템(mock)에 처리를 요청하고, 결과물(잘라낸 GeoTIFF)을 받아 MinIO에 저장합니다.
- 일시적인 오류는 지수 백오프로 재시도하고, 재시도를 다 써도 실패하면 FAILED로 둡니다.

**심화**: 처리 시작 전 주문 취소, 처리 중 서버가 재시작됐을 때 작업 복구, 다운로드 이력

**학습 포인트**: 비동기 작업 리소스(202와 상태 조회), 멱등성, 재시도·백오프·타임아웃, 서명 URL, SSE

### 9. 주문 관리

**필수**

- 주문 목록: 기간·상태·고객·금액 필터, 주문번호·고객 검색, 정렬, 페이지 번호
- 주문 상세: 항목별 상태, 처리 로그, 지도에 주문 영역 표시
- 대형 주문 승인과 반려(사유 입력), 실패 항목 재처리, 취소
- 여러 주문을 한 번에 처리하고, 일부만 실패하면 그 결과를 보여 줍니다.
- CSV 내보내기

**심화**: 필터 조건 저장, 목록 실시간 갱신

**학습 포인트**: 서버 사이드 필터 쿼리와 인덱스, 일괄 작업의 부분 실패, 스트리밍 응답

### 10. 대시보드

**필수**

- KPI: 오늘 주문 수, 매출, 처리 실패율, 평균 처리 시간
- 기간별 주문·매출 추이, 센서별 비율
- 주문 AOI 히트맵 (육각형 그리드 집계)
- 작업 큐 현황 (대기, 진행, 실패)

**심화**: 기간 비교(전주 대비), 집계 캐시

**학습 포인트**: 집계 쿼리와 시계열 버킷, 공간 집계(H3), 캐시 전략

### 11. 고급 지도 도구

**필수**

- AOI 그리기(사각형, 다각형), 수정, 삭제
- GeoJSON·KML 파일을 올려 AOI로 지정합니다. 유효성을 검사하고, 너무 복잡하면 단순화합니다.
- 시군구 이름으로 검색해 그 경계를 AOI로 씁니다.
- 내 AOI 저장, 목록, 불러오기
- 거리·면적 측정, 마우스 위치 좌표 표시, 배경 지도 전환

**심화**: Shapefile(zip) 업로드, 좌표 직접 입력(도·분·초)

**학습 포인트**: 그리기 도구(terra-draw), 공간 파일 파싱, 폴리곤 유효성과 단순화, 행정경계 데이터

### 12. 영상 뷰어

**필수**

- 영상 상세 화면에서 실제 Sentinel-2 영상을 지도 위에 띄웁니다(titiler 동적 타일).
- 밴드 조합을 전환합니다: 트루컬러, 근적외선 위색.
- 두 시점의 영상을 스와이프로 비교합니다.

**심화**: 밝기·대비 조절, 지점의 픽셀 값 조회, NDVI 표시

**학습 포인트**: COG 구조(내부 타일, overview), 동적 타일링과 XYZ, 재투영(UTM에서 EPSG:3857로), 밴드 조합

### 13. 촬영 요청

**필수**

- 고객: 촬영 요청 생성(AOI, 희망 기간, 센서, 최대 운량, 우선순위), 내 요청 목록과 상태
- 백오피스:
  - 요청 목록과 검토
  - 수락과 반려 (사유 입력)
  - 촬영 일정 배정
  - 촬영 완료 처리 (카탈로그 영상과 연결)
- 상태가 바뀌면 고객에게 알립니다. 14단계 전이라면 로그로 대신합니다.

**심화**: 면적과 우선순위로 견적 산정, 일정 충돌 표시

**학습 포인트**: 워크플로 상태 머신, 역할별로 허용되는 전이, 상태 이력 기록

### 14. 모니터링과 알림

**필수**

- 고객: 검색 조건 저장, 새 영상 알림 구독, 알림 센터(목록, 읽음 처리), 실시간 푸시(SSE)
- 주기 수집 작업이 새 영상을 가져오면 저장된 검색과 맞춰 보고 알림을 만듭니다.
- 같은 영상으로 같은 사용자에게 알림을 두 번 보내지 않습니다.

**심화**: 하루 요약 알림, 이메일 채널(콘솔 출력으로 대신)

**학습 포인트**: 스케줄러와 반복 작업, 증분 매칭, 팬아웃, 유니크 키로 중복 방지

### 15. AI 분석

**필수**

- 고객: 영상과 AOI를 골라 분석을 요청합니다.
  - 분석 종류: 객체 탐지(선박, 건물), 변화 탐지(두 시점)
  - 진행률 표시
  - 결과를 지도 레이어로 겹쳐 보기
  - 결과 다운로드(GeoJSON)
- worker가 AI 모델(mock)에 작업을 넘기고 진행률을 받아 갱신합니다.

**심화**: 결과 통계(객체 수, 변화 면적), 결과가 많을 때 벡터 타일로 렌더링

**학습 포인트**: 분석 파이프라인, 오래 걸리는 작업의 진행률, 결과 저장 형식(GeoJSON, FlatGeobuf)

### 16. PostGIS와 성능

**필수**

- `compose.yaml`의 Postgres를 PostGIS 이미지로 바꿉니다.
- footprint를 `geometry(MultiPolygon, 4326)` 컬럼으로 옮기고 GIST 인덱스를 만듭니다.
- 검색은 `ST_Intersects`, 커버리지는 `ST_Intersection`과 `ST_Area(geography)`로 구현해 리포지토리를 바꿉니다.
- 메모리 구현과 결과가 같은지 비교하는 테스트를 작성합니다.
- 영상 수만 건에서 메모리 구현과 PostGIS의 성능을 비교하고, 실행 계획(EXPLAIN)을 분석합니다.

**심화**: footprint를 벡터 타일(`ST_AsMVT`)로 서빙, 히트맵 집계를 SQL로 이동

**학습 포인트**: SRID, geometry와 geography, 공간 인덱스, 실행 계획, MVT

### 17. 배포와 운영

**필수**

- web, api, worker의 Dockerfile(멀티 스테이지)을 만들고 compose 하나로 전체를 띄웁니다.
- `/api/health`(liveness)와 `/api/ready`(DB·Redis 연결 확인)를 둡니다.
- pino 구조화 로그에 요청 id를 붙이고, web에서 api, worker까지 전달합니다.
- rate limit(Redis)과 graceful shutdown(진행 중인 작업 마무리)을 적용합니다.
- 장애 주입: mock 처리 시스템을 내렸다 올려도 주문이 복구되는지 확인합니다.

**심화**: Prometheus 메트릭, CI(lint, test, build), 클라우드 배포

**학습 포인트**: 컨테이너 이미지, 관측성(로그, 메트릭, 트레이스), 장애 대응

## 개발 방식

- 로드맵의 단계를 하나씩 구현합니다. 선행 단계만 지키면 순서는 자유이고, GIS부터 가려면 1 → 2 → 3 → 11 → 12 → 16 순서를 권합니다.
- 각 단계의 **필수**는 완료 기준이고, **심화**는 여유가 있을 때 하는 것입니다.
- 명세가 모호하면 가정을 세우고 진행한 뒤, 그 가정을 [docs/decisions.md](docs/decisions.md)에 적습니다.
- 스냅샷 데이터의 품질 문제와 mock 외부 시스템의 동작은 직접 발견하는 것이 공부입니다. `mock/` 소스와 `docs/answers/`는 해당 단계를 끝낸 뒤에 엽니다.
- 개발 환경 설정과 명령어는 [docs/development.md](docs/development.md)에 있습니다.
