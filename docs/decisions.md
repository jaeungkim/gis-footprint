# 결정 기록

되돌리기 어렵거나 나중에 보면 이유가 안 보일 결정을 적는다. 구현하다가 세운 가정도 여기에 추가한다.

## 아키텍처

### 전부 로컬에서 돌린다

- **결정**: 클라우드 계정, 유료 서비스, API 키 없이 노트북 하나로 돌린다. 외부 시스템(STAC API, 영상 처리 시스템, AI 모델)은 `mock/`에 흉내 서버로 둔다. 파일은 로컬 디스크(`storage/`)에 저장하고 메타데이터와 샘플 영상은 저장소에 넣어 둔다. 예외는 배경 지도 하나로, OpenFreeMap 타일을 인터넷에서 받는다.
- **이유**: 공부용이라 비용이 0이어야 하고 인프라 설정보다 코드에 시간을 쓰고 싶다. 외부 서비스가 바뀌거나 내려가도 결과가 똑같이 나온다.
- **대안**: MinIO 같은 S3 호환 저장소. presigned URL을 실제 S3 API로 써 볼 수 있지만 컨테이너가 하나 늘고, 서명 URL 원리는 HMAC으로 직접 만들어 보는 편이 더 잘 보인다. 클라우드 배포와 CI/CD도 같은 이유로 지금은 안 한다.

### 모듈형 모놀리스 + worker

- **결정**: api는 NestJS 하나에 모듈로 나눈다. 비동기 작업은 같은 코드베이스의 별도 진입점(`src/worker.ts`)에서 처리한다.
- **이유**: 실제 서비스도 대부분 여기서 시작한다. 모듈 경계만 지키면 나중에 떼어낼 수 있고, 지금 서비스를 쪼개면 배포와 통신과 트랜잭션 비용만 는다.
- **대안**: 마이크로서비스. 팀과 트래픽이 커지고 모듈마다 배포 주기가 달라지면 다시 본다.

### 비동기 작업은 BullMQ + Redis

- **결정**: 수집, 주문 처리, 분석, 주기 작업을 BullMQ 큐로 돌린다.
- **이유**: 재시도, 백오프, 지연 작업, 반복 작업이 기본으로 있고 Nest 연동(`@nestjs/bullmq`)도 있다. Redis는 세션과 pub/sub에도 쓰니까 인프라가 늘지 않는다.
- **대안**: Postgres 기반 큐(pg-boss). 인프라는 줄지만 세션과 pub/sub 때문에 Redis가 어차피 필요하다.

### 카탈로그 저장은 단계적으로 옮긴다

- **결정**: 처음엔 메모리 + turf로 구현하고 6단계에서 Postgres에 저장하고 16단계에서 PostGIS로 옮긴다. 카탈로그는 리포지토리 인터페이스 뒤에 둔다.
- **이유**: 공간 연산 원리를 먼저 손으로 다뤄 보고, 같은 인터페이스에 구현만 바꿔 끼워서 결과와 성능을 비교하려고.
- **대안**: 처음부터 PostGIS. Prisma가 geometry 타입을 지원하지 않아서 raw SQL이 필요하고 시작 비용이 크다.

### 영상 타일과 잘라내기는 titiler

- **결정**: COG 동적 타일과 영역 잘라내기에 titiler 컨테이너를 쓴다. titiler는 `data/cogs`의 로컬 파일을 읽는다. 주문 산출물은 `storage/`에 두고 api가 서명한 만료 링크로 내려준다.
- **이유**: 많이 쓰는 오픈소스 동적 타일러라서 GDAL을 직접 안 만지고도 실제 영상을 자르고 보여 줄 수 있다.
- **대안**: 브라우저에서 COG를 직접 읽기. UTM 재투영과 밴드 조합을 클라이언트에서 해야 한다.

### 인증은 httpOnly 쿠키 세션 (Redis 저장)

- **결정**: 세션은 Redis에 두고 세션 id만 httpOnly 쿠키로 보낸다.
- **이유**: web이 `/api/*`를 같은 origin으로 rewrite해서 CORS가 필요 없다. 사용자를 정지하면 세션을 바로 끊을 수 있고 토큰이 JavaScript에 노출되지 않는다.
- **대안**: JWT access + refresh. 서버가 상태를 안 갖지만 바로 무효화하기 어렵다. 모바일이나 서드파티 같은 외부 클라이언트가 생기면 다시 본다.

### 실시간은 SSE + Redis pub/sub

- **결정**: 주문 상태와 알림은 SSE로 보낸다. worker에서 api로 가는 이벤트는 Redis pub/sub을 쓴다.
- **이유**: 서버에서 클라이언트로 가는 단방향 푸시만 필요하다. SSE는 그냥 HTTP라서 재연결이 기본으로 된다.
- **대안**: WebSocket. 양방향이 필요해지면 다시 본다.
