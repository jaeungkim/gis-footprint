# 결정 기록

되돌리기 어렵거나 나중에 보면 이유가 안 보일 결정을 적는다. 구현하다가 세운 가정도 여기에 추가한다.

## 아키텍처

### 전부 로컬에서 돌린다

- **결정**: 클라우드 계정, 유료 서비스, API 키 없이 노트북 하나로 돌린다. 외부 시스템(STAC API, 영상 처리 시스템, AI 모델)은 `mock/`에 흉내 서버로 둔다. 파일은 로컬 디스크(`storage/`)에 저장하고 메타데이터와 샘플 영상은 저장소에 넣어 둔다. 예외는 배경 지도 하나로, OpenFreeMap 타일을 인터넷에서 받는다.
- **이유**: 공부용이라 비용이 0이어야 하고 인프라 설정보다 코드에 시간을 쓰고 싶다. 외부 서비스가 바뀌거나 내려가도 결과가 똑같이 나온다.
- **대안**: MinIO 같은 S3 호환 저장소. presigned URL을 실제 S3 API로 써 볼 수 있지만 컨테이너가 하나 늘고, 서명 URL 원리는 HMAC으로 직접 만들어 보는 편이 더 잘 보인다. 클라우드 배포와 CI/CD도 같은 이유로 지금은 안 한다.

### 모듈형 모놀리스 + worker

- **결정**: api는 NestJS 하나에 모듈로 나눈다. 비동기 작업은 같은 코드베이스의 별도 진입점(`src/worker.ts`)에서 처리한다.
- **이유**: 실제 서비스도 대부분 여기서 시작한다. 모듈 경계만 지키면 나중에 떼어낼 수 있고, 지금 서비스를 쪼개면 배포와 통신과 트랜잭션 비용만 는다.
- **대안**: 마이크로서비스. 팀과 트래픽이 커지고 모듈마다 배포 주기가 달라지면 다시 본다.

### 비동기 작업은 BullMQ + Redis

- **결정**: 수집, 주문 처리, 분석, 주기 작업을 BullMQ 큐로 돌린다.
- **이유**: 재시도, 백오프, 지연 작업, 반복 작업이 기본으로 있고 Nest 연동(`@nestjs/bullmq`)도 있다. Redis는 세션과 pub/sub에도 쓰니까 인프라가 늘지 않는다.
- **대안**: Postgres 기반 큐(pg-boss). 인프라는 줄지만 세션과 pub/sub 때문에 Redis가 어차피 필요하다.

### 카탈로그 저장은 단계적으로 옮긴다

- **결정**: 처음엔 메모리 + turf로 구현하고 6단계에서 Postgres에 저장하고 16단계에서 PostGIS로 옮긴다. 카탈로그는 리포지토리 인터페이스 뒤에 둔다.
- **이유**: 공간 연산 원리를 먼저 손으로 다뤄 보고, 같은 인터페이스에 구현만 바꿔 끼워서 결과와 성능을 비교하려고.
- **대안**: 처음부터 PostGIS. Prisma가 geometry 타입을 지원하지 않아서 raw SQL이 필요하고 시작 비용이 크다.

### 영상 타일과 잘라내기는 titiler

- **결정**: COG 동적 타일과 영역 잘라내기에 titiler 컨테이너를 쓴다. titiler는 `data/cogs`의 로컬 파일을 읽는다. 주문 산출물은 `storage/`에 두고 api가 서명한 만료 링크로 내려준다.
- **이유**: 많이 쓰는 오픈소스 동적 타일러라서 GDAL을 직접 안 만지고도 실제 영상을 자르고 보여 줄 수 있다.
- **대안**: 브라우저에서 COG를 직접 읽기. UTM 재투영과 밴드 조합을 클라이언트에서 해야 한다.

### 인증은 httpOnly 쿠키 세션 (Redis 저장)

- **결정**: 세션은 Redis에 두고 세션 id만 httpOnly 쿠키로 보낸다.
- **이유**: web이 `/api/*`를 같은 origin으로 rewrite해서 CORS가 필요 없다. 사용자를 정지하면 세션을 바로 끊을 수 있고 토큰이 JavaScript에 노출되지 않는다.
- **대안**: JWT access + refresh. 서버가 상태를 안 갖지만 바로 무효화하기 어렵다. 모바일이나 서드파티 같은 외부 클라이언트가 생기면 다시 본다.

### 실시간은 SSE + Redis pub/sub

- **결정**: 주문 상태와 알림은 SSE로 보낸다. worker에서 api로 가는 이벤트는 Redis pub/sub을 쓴다.
- **이유**: 서버에서 클라이언트로 가는 단방향 푸시만 필요하다. SSE는 그냥 HTTP라서 재연결이 기본으로 된다.
- **대안**: WebSocket. 양방향이 필요해지면 다시 본다.

### 카탈로그 적재 (1단계)

- **문자열 운량은 숫자로 받는다**: `"33.29"`처럼 숫자로 읽히는 문자열은 숫자로 바꾼다. 숫자로 안 읽히거나 0~100 밖이면 뺀다. 값의 뜻이 분명해서 버릴 이유가 없다. / 1, 6
- **시계 방향 링은 뒤집어서 적재한다**: RFC 7946은 파서가 방향이 틀렸다고 거부하지 말라고 한다. 바깥 링은 반시계, 구멍은 시계로 맞춰서 저장한다. / 1, 2, 16
- **추측해야 고칠 수 있는 건 뺀다**: 닫히지 않은 링, 자기 교차하는 링, 경위도 범위 밖 좌표(위경도가 뒤바뀐 것 포함), 시간대 없는 `datetime`은 고치지 않고 제외한다. 링 끝에 점이 빠졌는지 잘렸는지, 시간대가 UTC인지 KST인지 데이터만 보고는 알 수 없다. / 1, 6
- **EO인데 운량이 없으면 null로 적재한다**: 영상 자체는 멀쩡하다. 최대 운량 조건으로 검색하면 모르는 값이라 결과에서 빠진다. / 1, 2
- **편파(`sar:polarizations`)나 촬영 모드(`sar:instrument_mode`)가 없는 SAR는 뺀다**: 경고만 남기고 적재할 수도 있지만 VV/VH 중 뭐가 있는지 모르면 뷰어와 주문에서 쓸 수 없다. / 1, 12
- **STAC `bbox`는 안 읽는다**: geometry와 어긋난 Item이 있다. 필요하면 geometry에서 계산한다. / 1, 2
- **SAR의 운량 값은 무시한다**: SAR는 구름을 뚫고 찍으니 운량이 의미가 없다. 원본에 있어도 null로 둔다. / 1
- **썸네일은 브라우저에서 열리는 https 링크만 쓴다**: 없거나 `s3://`(S1, 요금 버킷)면 null. / 1, 3
- **같은 id가 또 나오면 `properties.updated`가 늦은 쪽을 남긴다**: 시각이 같으면 먼저 나온 쪽. 6단계 upsert도 같은 규칙을 쓴다. / 1, 6
- **id가 다르면 같은 촬영의 재처리본(`_0_`, `_1_`)이어도 둘 다 적재한다**: Earth Search에서 별개 Item이다. 검색 결과에서 하나로 합칠지는 2단계에서 다시 본다. / 1, 2
- **카탈로그 파일을 못 읽으면 서버가 안 뜬다**: Item 하나가 불량인 것과 달리 파일이 없거나 FeatureCollection이 아니면 설정 문제라 바로 실패시킨다. / 1

### 탐색 화면 (3단계)

- **지역을 안 고르면 전체 카탈로그를 검색한다**: 첫 화면에도 결과가 보인다. 공간 조건이 없으니 커버리지는 안 보이고 커버리지 정렬은 고를 수 없다(URL에 있으면 최신순으로). / 3
- **광학과 레이더를 같이 고르면 운량 조건은 광학에만 건다**: CQL2에서 SAR의 null 운량은 비교에서 떨어진다. `or(collection = 'sentinel-1-grd', eo:cloud_cover <= X)`로 SAR를 살린다. 광학을 끄면 운량 슬라이더도 끈다. / 2, 3
- **위성 조건은 다른 조건과 AND**: 안 고르면 전체. 위성 목록은 `/api/stac/collections`의 `summaries.platform`이고 켠 센서 것만 보인다. 센서를 끄면 그 센서 위성 선택도 지운다. / 3
- **촬영 기간은 KST 날짜 양끝 포함**: `from`은 `T00:00:00+09:00`, `to`는 `T23:59:59.999+09:00`. 시작이 끝보다 늦으면 검색하지 않고 입력 옆에 알린다. / 2, 3
- **운량 슬라이더는 놓을 때 URL에 반영한다**: 드래그 중 값마다 검색이 나가지 않게. / 3
- **footprint는 아주 옅게(2%) 채운다**: 테두리만 그리면 작은 AOI로 확대했을 때 100km가 넘는 footprint 테두리가 전부 화면 밖이라 결과가 안 보인다. 겹친 만큼 진해져서 몇 장이 덮는지도 보인다. 결과가 한두 장이면 거의 안 보이는 건 한계. / 3
- **4xx 검색 오류와 형식이 틀린 응답은 재시도하지 않는다**: 같은 요청은 같은 400을 받고, zod 검사에 실패한 응답도 다시 받아 봐야 같다. 5xx와 네트워크 오류만 TanStack 기본대로 재시도한다. / 3
- **기간 빠른 선택은 "최근 n일"이 아니라 데이터가 있는 달**: 카탈로그가 고정 스냅샷(2026-07~08)이라 오늘 기준 프리셋은 빈 결과가 난다. 컬렉션 `extent.temporal`에서 최근 3달을 만들고 달력도 그 마지막 달부터 연다. / 3
- **검색 결과 Item에 `gsd`를 넣는다**: 필터 queryable은 `gsd`인데 원본 S2 Item은 gsd를 asset에만 둔다. 카드에 해상도를 보여 주려고 STAC 공통 메타데이터 `properties.gsd`에 DB의 `gsd_m`을 넣는다. / 2, 3
- **겹친 footprint는 클릭 지점 목록으로 고른다**: 한 장이면 바로 선택, 여러 장이면 팝업, 빈 곳은 선택 해제. 목록에서 고르면 그 footprint와 AOI가 다 보이게 지도를 옮기고, 지도에서 고르면 안 옮긴다. / 3
- **필터는 접을 수 있고 처음엔 모바일만 접힌다**: 접으면 바뀐 조건만 칩으로 보인다. 초기화는 정렬까지 URL의 검색 조건을 다 지운다. / 3
