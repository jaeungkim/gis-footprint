# 결정 기록

되돌리기 어렵거나, 나중에 보면 이유가 안 보이는 결정을 적습니다. 구현하면서 세운 가정도 여기에 추가합니다.

## 아키텍처

### 모듈형 모놀리스 + worker

- **결정**: api는 NestJS 하나에 모듈로 나누고, 비동기 작업은 같은 코드베이스의 별도 진입점(`src/worker.ts`)에서 처리합니다.
- **이유**: 실제 서비스도 대부분 여기서 시작합니다. 모듈 경계를 지키면 나중에 서비스로 떼어낼 수 있고, 지금 단계에서 서비스를 쪼개면 배포·통신·트랜잭션 비용만 늘어납니다.
- **대안**: 마이크로서비스. 팀과 트래픽이 커지고 모듈별로 배포 주기가 달라질 때 다시 검토합니다.

### 비동기 작업은 BullMQ + Redis

- **결정**: 수집, 주문 처리, 분석, 주기 작업을 BullMQ 큐로 처리합니다.
- **이유**: 재시도, 백오프, 지연 작업, 반복 작업이 기본 기능으로 있고, Nest 연동(`@nestjs/bullmq`)이 있습니다. Redis는 세션과 pub/sub에도 쓰므로 인프라가 늘지 않습니다.
- **대안**: Postgres 기반 큐(pg-boss). 인프라는 줄지만 세션과 pub/sub에 Redis가 어차피 필요합니다.

### 카탈로그 저장은 단계적으로 전환

- **결정**: 처음에는 메모리 + turf로 구현하고, 6단계에서 Postgres에 저장하고, 16단계에서 PostGIS로 옮깁니다. 카탈로그는 리포지토리 인터페이스 뒤에 둡니다.
- **이유**: 공간 연산의 원리를 먼저 직접 다뤄 보고, 같은 인터페이스로 구현을 바꿔 끼우며 결과와 성능을 비교합니다.
- **대안**: 처음부터 PostGIS. Prisma가 geometry 타입을 지원하지 않아 raw SQL이 필요하고, 초기 진입 비용이 큽니다.

### 영상 타일과 주문 산출물은 titiler

- **결정**: COG 동적 타일과 영역 잘라내기에 titiler 컨테이너를 씁니다. 산출물은 MinIO에 저장하고 서명 URL로 내려줍니다.
- **이유**: 업계 표준 동적 타일러이고, 직접 GDAL을 다루지 않고도 실제 영상을 자르고 보여 줄 수 있습니다.
- **대안**: 브라우저에서 COG를 직접 읽는 방식. UTM 재투영과 밴드 조합을 클라이언트에서 처리해야 합니다.

### 인증은 httpOnly 쿠키 세션 (Redis 저장)

- **결정**: 서버 세션을 Redis에 두고, 세션 id만 httpOnly 쿠키로 보냅니다.
- **이유**: web이 `/api/*`를 같은 origin으로 rewrite하므로 CORS가 필요 없습니다. 사용자를 정지하면 세션을 즉시 끊을 수 있고, 토큰이 JavaScript에 노출되지 않습니다.
- **대안**: JWT access + refresh 토큰. 서버가 상태를 갖지 않지만 즉시 무효화가 어렵습니다. 외부 클라이언트(모바일, 서드파티)가 생기면 다시 검토합니다.

### 실시간은 SSE + Redis pub/sub

- **결정**: 주문 상태와 알림은 SSE로 보냅니다. worker에서 api로 가는 이벤트는 Redis pub/sub을 씁니다.
- **이유**: 서버에서 클라이언트로 가는 단방향 푸시만 필요합니다. SSE는 HTTP 위에서 동작하고 재연결이 기본으로 들어 있습니다.
- **대안**: WebSocket. 양방향 통신이 필요해지면 다시 검토합니다.
