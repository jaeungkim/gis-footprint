# 로드맵

선행 단계만 지키면 순서는 상관없다. **필수**를 다 하면 그 단계는 끝이고 **심화**는 여유 있을 때 한다. 명세가 애매하면 가정을 세우고 진행한 다음 [decisions.md](decisions.md)에 적어 둔다.

main에서 바로 작업하고 단계가 끝날 때마다 리뷰를 받는다. 커밋 전에 `pnpm lint`와 테스트가 통과해야 한다. 리뷰에서 나온 얘기 중 남길 만한 건 decisions.md에 같이 적는다.

## 1. 카탈로그 적재

BE. 선행 없음.

**필수**

- 서버가 뜰 때 `data/catalog/items.json`(STAC ItemCollection)을 읽어서 카탈로그에 올린다.
- 유효하지 않은 Item은 빼고 id와 사유를 로그로 남긴다. 불량 Item이 있어도 서버는 정상으로 떠야 하고 마지막에 적재 요약(n건 적재 / 전체 m건)을 찍는다.
- STAC 속성을 플랫폼 모델로 정규화한다. 센서(EO/SAR), 위성, 촬영 시각, 운량(EO만), 해상도(GSD), footprint, 썸네일.
- `GET /api/scenes/:id`는 단건을 GeoJSON Feature로 준다. 없으면 404.
- 카탈로그는 리포지토리 인터페이스 뒤에 둔다. 처음엔 메모리로 구현하고 6단계에서 Postgres, 16단계에서 PostGIS로 바꾼다.

**심화**: 검증 로직 단위 테스트, 제외 통계를 `/api/health`에 노출

**공부할 것**: GeoJSON 규칙(RFC 7946 좌표 순서, 링 닫힘, 오른손 법칙), STAC Item 구조(properties, assets, links, eo/sar/proj 확장), EPSG:4326, 스키마 검증

## 2. 영상 검색 API

BE. 선행 1.

**필수**

- AOI와 겹치는 영상을 찾는 검색 API를 설계하고 만든다. [STAC API Item Search](https://github.com/radiantearth/stac-api-spec/tree/main/item-search)를 참고한다.
- 검색 조건
  - AOI (GeoJSON Polygon 또는 MultiPolygon)
  - 촬영 기간 (한국 시간 날짜, 양끝 포함)
  - 센서 (여러 개 선택)
  - 최대 운량
  - 최대 해상도(GSD)
  - 위성
- 정렬은 최신순(기본), 커버리지 높은순, 운량 낮은순.
- 응답은 GeoJSON FeatureCollection이다. 영상마다 AOI 중 그 영상이 덮는 면적(km²)과 비율(%)을 넣고 다음 페이지 커서를 같이 준다.
- 잘못된 요청은 400 Problem Details.
- 필터와 커버리지 계산 단위 테스트를 쓴다.

**심화**: bbox 사전 필터와 성능 측정, GET 방식 검색과 비교, STAC API 호환 엔드포인트(`/api/stac/search`)

**공부할 것**: 교차 판정(bbox 사전 필터, 정밀 교차), 구면 면적과 평면 면적, 시간대와 날짜 경계, STAC API, 커서와 오프셋 페이지네이션

## 3. 탐색 화면

FE. 선행 2.

**필수**

- 지도, 필터 패널, 결과 목록으로 된 탐색 화면을 만든다.
- 샘플 AOI를 고르면 지도가 그 영역으로 가고 AOI를 그린다.
- 결과 footprint를 지도에 그린다. 목록에서 hover나 클릭하면 지도에서 강조하고, 지도에서 클릭하면 목록의 그 항목으로 스크롤한다.
- 결과 항목에는 썸네일, 위성, 촬영 시각(한국 시간), 운량, 커버리지를 보여 준다.
- 검색 조건은 URL에 둔다. 새로고침하거나 링크를 공유해도 같은 결과가 나와야 한다.
- 로딩, 결과 없음, 에러 상태가 있어야 한다.
- 결과는 무한 스크롤로 이어서 불러온다.

**심화**: 선택한 영상의 썸네일을 footprint 위에 겹쳐 보기, footprint가 많을 때 렌더링 성능, 모바일 레이아웃

**공부할 것**: MapLibre의 source, layer, feature-state, EPSG:3857과 4326, URL 상태와 지도 상태 분리, 서버 상태 캐싱

## 4. 인증과 역할

풀스택. 선행 없음.

**필수**

- 회원가입, 로그인, 로그아웃. 비밀번호는 argon2로 해시한다.
- httpOnly 쿠키 세션을 쓰고 세션은 Redis에 둔다.
- 역할은 CUSTOMER, OPERATOR, ADMIN. API는 Guard와 역할 데코레이터로, web은 middleware로 막는다.
- `/admin` 레이아웃(사이드바, 헤더)을 만들고 권한이 없으면 못 들어가게 한다.
- seed로 역할별 데모 계정을 만든다.

**심화**: 비밀번호 재설정(메일은 콘솔 출력으로 대신), 로그인 실패 횟수 제한

**공부할 것**: 세션과 JWT 비교, RBAC, SameSite 쿠키와 CSRF, 비밀번호 해싱

## 5. 사용자 관리

풀스택. 선행 4.

**필수**

- 고객: 내 정보 수정, 비밀번호 변경, 탈퇴(소프트 삭제)
- 백오피스
  - 사용자 목록 (이름과 이메일 검색, 역할과 상태 필터, 정렬, 페이지 번호)
  - 사용자 상세와 역할 변경
  - 정지와 해제 (정지하면 그 사용자 세션을 바로 끊는다)
  - 초대 링크로 운영자 추가 (일회용, 만료 있음)
- 감사 로그를 넣는다. 운영자와 관리자가 뭔가 바꾸면 interceptor가 자동으로 기록하고 백오피스에서 볼 수 있다.

**심화**: 관리자가 다른 사용자로 로그인해서 보기(impersonation, 감사 로그 필수)

**공부할 것**: 일회용 토큰, 소프트 삭제와 개인정보 처리, 세션 무효화, interceptor 기반 감사 로그

## 6. 상품 관리와 수집

풀스택. 선행 1, 4.

**필수**

- 카탈로그를 Postgres에 저장한다. footprint는 JSON 컬럼에 두고 공간 검색은 계속 메모리 인덱스로 한다.
- worker(BullMQ)를 넣는다. 수집 작업은 기간, 지역, 컬렉션을 받아서 `mock/stac-api`에서 Item을 가져오고 검증한 다음 upsert한다.
- 수집 이력(IngestRun)에 상태, 신규/갱신/제외 건수, 제외 사유를 남긴다.
- 백오피스
  - 상품 목록 (검색, 필터, 정렬)
  - 상품 상세 (지도, 메타데이터, 원본 STAC JSON)
  - 공개와 숨김
  - 수집 실행과 이력 화면

**심화**: 실패한 수집 재시도, 수집 진행률 실시간 표시

**공부할 것**: 외부 API 페이지 순회(STAC `next` 링크), 멱등 upsert, 증분 수집, 배치 작업과 재시도

## 7. 장바구니와 가격

풀스택. 선행 2, 4.

**필수**

- 고객이 영상을 장바구니에 담을 때 잘라낼 AOI를 정하고, 잘린 영역(footprint와 AOI의 교집합)을 미리 본다.
- 견적은 잘린 면적 × 단가이고 최소 주문 면적이 있다. 견적 계산은 서버에서만 한다.
- 백오피스에서 가격 정책을 관리한다 (센서와 해상도 등급별 km² 단가, 최소 면적, 유효 기간).

**심화**: 장바구니에 담은 뒤 가격이 바뀐 경우 처리

**공부할 것**: 공간 clip, 금액 계산(원 단위 정수, 반올림 규칙), 가격 버전과 유효 기간

## 8. 주문과 처리

풀스택. 선행 6, 7.

**필수**

- 고객
  - 장바구니로 주문 생성 (`Idempotency-Key`)
  - 주문 내역과 상세
  - 상태 실시간 갱신 (SSE)
  - 끝난 주문 다운로드
- 주문할 때의 가격을 스냅샷으로 남긴다.
- worker가 처리 시스템(mock)에 요청하고 결과물(잘라낸 GeoTIFF)을 받아서 `storage/`에 저장한다.
- 다운로드 링크는 직접 만든다. api가 파일 경로와 만료 시각을 HMAC으로 서명해서 링크를 주고, 요청이 오면 서명을 확인한 뒤 `storage/`에서 파일을 스트리밍한다.
- 일시적인 오류는 지수 백오프로 재시도하고, 재시도를 다 써도 실패하면 FAILED로 둔다.

**심화**: 처리 시작 전 주문 취소, 처리 중에 서버가 재시작됐을 때 작업 복구, 다운로드 이력, 처리 시스템이 끝나면 webhook으로 알려 주는 방식(서명 검증, 같은 webhook이 두 번 와도 한 번만 처리)

**공부할 것**: 비동기 작업 리소스(202와 상태 조회), 멱등성, 재시도와 백오프와 타임아웃, 폴링과 webhook, 서명 URL 원리, SSE

**필수**

**심화**: 필터 조건 저장, 목록 실시간 갱신

**공부할 것**: 서버 사이드 필터 쿼리와 인덱스, 일괄 작업의 부분 실패, 스트리밍 응답

## 15. AI 분석

풀스택. 선행 6.

**필수**

- 고객이 영상과 AOI를 골라 분석을 요청한다.
  - 분석 종류: 객체 탐지(선박, 건물), 변화 탐지(두 시점)
  - 진행률 표시
  - 결과를 지도 레이어로 겹쳐 보기
  - 결과 다운로드(GeoJSON)
- worker가 파이프라인을 돌린다.
  - 전처리: AOI만큼 영상을 잘라서 모델 입력 크기의 타일로 나눈다.
  - 추론: 타일을 AI 모델(mock)에 넘기고 진행률을 받아서 갱신한다.
  - 후처리: 모델이 준 픽셀 좌표를 영상의 geotransform으로 지도 좌표(EPSG:4326)로 바꾸고, 타일 경계에 걸려 두 번 잡힌 객체를 합친다.
- 단계마다 실패하면 어디서 멈췄는지 남기고 그 단계부터 다시 돌릴 수 있다.

**심화**: 결과 통계(객체 수, 변화 면적), 결과가 많을 때 벡터 타일로 렌더링, mock 대신 로컬에서 도는 작은 실제 모델(ONNX) 붙이기

**공부할 것**: 분석 파이프라인 단계 나누기, 픽셀 좌표와 지도 좌표 변환, 오래 걸리는 작업의 진행률, 결과 저장 형식(GeoJSON, FlatGeobuf)

## 16. PostGIS와 성능

BE. 선행 6.

**필수**

- `compose.yaml`의 Postgres를 PostGIS 이미지로 바꾼다.
- footprint를 `geometry(MultiPolygon, 4326)` 컬럼으로 옮기고 GIST 인덱스를 건다.
- 검색은 `ST_Intersects`, 커버리지는 `ST_Intersection`과 `ST_Area(geography)`로 다시 구현해서 리포지토리를 갈아 끼운다.
- 메모리 구현과 결과가 같은지 비교하는 테스트를 쓴다.
- 영상 수만 건에서 메모리 구현과 PostGIS 성능을 비교하고 실행 계획(EXPLAIN)을 본다.
- k6로 검색 API에 부하를 걸어서 바꾸기 전과 후의 응답 시간(p95)을 숫자로 남긴다.

**심화**: footprint를 벡터 타일(`ST_AsMVT`)로 서빙, 히트맵 집계를 SQL로 옮기기, GeoServer를 붙여서 PostGIS 테이블을 WMS/WFS로 내보내고 지도와 QGIS에서 열어 보기

**공부할 것**: SRID, geometry와 geography, 공간 인덱스, 실행 계획, MVT, 부하 테스트, OGC 표준(WMS, WFS, WMTS)

## 17. 운영과 안정화

인프라. 언제든.

**필수**

- `/api/health`(liveness)와 `/api/ready`(DB, Redis 연결 확인)를 둔다.
- pino 구조화 로그에 요청 id를 붙이고 web에서 api, worker까지 넘긴다.
- rate limit(Redis)과 graceful shutdown(진행 중인 작업 마무리)을 넣는다.
- 장애를 일부러 낸다. mock 처리 시스템을 내리거나 느리게 만들고, Redis를 재시작해 보고, 그동안 주문이 멈추지 않고 나중에 복구되는지 확인한다.
- 장애마다 기록을 남긴다(`docs/incidents/`). 증상, 원인, 어떻게 알았는지, 어떻게 고쳤는지, 다시 안 나게 뭘 바꿨는지.

**심화**: Prometheus와 Grafana로 메트릭 대시보드(로컬 compose), 외부 호출에 서킷 브레이커, 느린 쿼리 로그

**공부할 것**: 관측성(로그, 메트릭, 트레이스), 장애 주입, 타임아웃과 서킷 브레이커, 장애 회고

## 18. 기업 고객 기능

풀스택. 선행 5, 7.

**필수**

- 조직(기업 고객) 계정과 멤버 관리. 조직 관리자가 멤버를 초대하고 내보낸다.
- 조직별 계약 단가. 견적을 낼 때 기본 가격 정책보다 먼저 적용한다.
- 조직 안에서 AOI, 저장한 검색, 주문을 같이 본다. 다른 조직 데이터는 절대 안 보여야 하고 테스트로 확인한다.
- 월별 사용량 리포트(주문 수, 면적, 금액)를 화면과 CSV로 준다.

**심화**: 조직별 기본 설정(기본 센서, 최대 운량, 알림 채널), 조직 단위 사용 한도

**공부할 것**: 멀티테넌시와 데이터 격리, 권한 범위(조직 안 역할), 가격 우선순위
